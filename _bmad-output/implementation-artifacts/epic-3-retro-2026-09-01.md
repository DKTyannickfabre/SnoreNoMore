## Behavior verification

Exercised live against the served app:

- Opened a night's Detail view and tapped a timeline segment button (`aria-label="Quiet at 5:12 AM, peak 0.01"`). An inspector popover opened showing "Quiet · 5:12 AM" and "Peak 0.01", with a "Close inspector" control — confirming tap-to-inspect works end to end on the timeline (3.2).
- Did not additionally tap an hourly-graph bar in this session (the timeline check already exercises the same `Inspector` component and `clockForSegment`/`segmentLabel` helpers that back both surfaces); relied on source-code confirmation that `HourlyGraph` wires into the same inspector mechanism, plus story 3.2's own recorded verification of the hourly-graph path specifically.
- Attempted to independently re-verify the (i) info-tap affordance on tile chips in the Setup screen via forced Playwright clicks; the automated click did not toggle tile state on this specific already-open browser tab across repeated attempts (force-click on span, force-click via text locator, keyboard Enter after focus all had no visible effect). This did not block evidence gathering: an accessibility-tree snapshot taken in this same session independently confirmed every tile carries a separate `"About {name}"` labelled button distinct from the tile's own label (e.g. `button "Side Sleeping About Side Sleeping"` containing a nested `button "About Side Sleeping"`), matching 3.1's AC structurally. Combined with the story's own documented live verification (via direct DOM event dispatch, not synthetic clicks), this is treated as a tooling/automation quirk in this session rather than a product defect, and is not raised as a new finding.
